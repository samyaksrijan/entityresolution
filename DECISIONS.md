# Decisions

## 2026-09-27 — Organizer resources are immutable

`student_resource/` is the common root of all supplied datasets and documentation. It is
ignored as a unit, and generated files live outside it.

## 2026-09-27 — Documentation overrides assumptions

The organizer README is authoritative. It explicitly requires open-set handling for France,
per-S1 macro F0.5 including singleton scoring, two final TSV outputs, no external lookup, and
an MIT/Apache-2.0 model of at most 8B parameters. No contradictory prior assumption was found.

## 2026-09-27 — Local verification interpreter

The project targets Python 3.11 and supports Python 3.12. Python 3.11 and `uv` were not
available on this machine, so verification uses a local `.venv` created with Python 3.12;
no system software was installed.

## 2026-09-27 — Bounded forensic blocking experiment

Exact name/address/digit channels were measured with 500 deterministic S1 queries against every
training S2/S3 target. Sparse TF-IDF channels used 100 deterministic S1 queries, full target scans,
a 40,000-feature vocabulary fitted on a deterministic 50,000-row target sample, cosine >= 0.35,
and a top-20 cap. Sampled measurements and extrapolated full candidate volumes are labelled in the
blocking report. A dense all-pairs matrix was not attempted because one source pair alone would
require roughly 40.9 TiB at float32.

## 2026-09-27 — Country is a hard retrieval partition

The full materialized set of 7,638,365 training positive edges has exact country agreement:
3,693,619 of 3,693,619 S2 edges and 3,944,746 of 3,944,746 S3 edges agree with S1. There are no
disagreement examples. Candidate generation therefore partitions by country. France transfer
remains an unverified test-time hypothesis because France has no training truth.

## 2026-09-27 — Optimized sparse top-N backend

Candidate retrieval uses `sparse-dot-topn==1.2.0`, licensed Apache-2.0, because it bounds result
nonzeros during sparse multiplication and supports merging top-N results across target batches.
A 200-query by 20,000-target benchmark was completed before the full sample scan. The code never
materializes a dense query-by-target matrix or a Cartesian pair table.

Full four-field/source target matrices were not persisted on the local machine. The benchmark
projects approximately 1.95 GB for the S2 name matrix and 2.05 GB for the S3 name matrix alone;
four matrices plus metadata and working space would be unsafe with the measured local free disk.
Instead, vectorizers, bounded benchmark matrices, resumable channel outputs, manifests, and
resource sidecars are persisted under `artifacts/blocking/`. The exact cloud command is recorded
in the candidate-generation report.

## 2026-09-27 — Fixed candidate evaluation sample and ID leakage rule

The evaluation sample contains 5,000 S1 entities selected by a hash of business text and country,
then round-robin sampled over truth strata. Retrieval scores and numeric entity-ID components do
not affect selection, features, blocks, sorting, or tie-breaking. All sampled S1 addresses are
present, so target-side missing-address status is reported as a post-selection annotation rather
than claiming an S1-missing-address measurement.

## 2026-09-27 — Candidate generation remains provisional

No measured union meets all selection targets. The K=80 all-view union has the highest measured
recall at 97.041% and oracle macro F0.5 of 0.98846, but averages 319.06 candidates per S1 with a
325.05 p95. Therefore the project does not emit the final competition `candidate_pairs.tsv` and
does not start pair-model training. Address digits are allowed only as evidence for pairs already
generated by name/address channels; a global digit block remains prohibited.
